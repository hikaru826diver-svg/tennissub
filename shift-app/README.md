# シフト作成WEBアプリ

アルバイトスタッフのシフト希望回収から、シフト表作成・日毎タイムテーブル・給与計算・Excel出力までを行うWebアプリです。
（React + Vite / データ保存は Supabase、未設定時はブラウザ内保存）

## 画面構成

| URL | 画面 | 内容 |
|---|---|---|
| `#staff` | **シフト希望入力**（アルバイト用） | 部門選択 → 氏名選択 → カレンダーで日付を複数選択 → 日毎に希望時間（終日可も可）→ 備考 → 提出。提出済み希望の確認・取消 |
| `#admin-requests` | 希望一覧 | 年月・部門・日付で絞込み。日付別／一覧／**未提出者**表示。希望をワンクリックでシフトに反映 |
| `#admin-shifts` | シフト作成ツール | 部門×月のシフト表。セルクリックで時間・休憩を編集（分割勤務可）、パターン入力モード、希望の一括反映、日別人数・労働時間・人件費、スタッフ別日数・時間・給与概算 |
| `#admin-timetable` | 日毎タイムテーブル | シフト作成ツールのシフトを自動反映した15分単位のガントチャート、時間帯ごとの配置人数 |
| `#admin-payroll` | 給与計算 | 単月（給与締め日に対応）または任意の期間で、スタッフ別・部門別・日毎・月別に自動計算 |
| `#admin-staff` | スタッフマスタ | 氏名・フリガナ・区分・時給・交通費（1日）・所属部門（複数可）・在籍状況 |
| `#admin-depts` | 部門マスタ | 部門名・表示色・並び順 |
| `#admin-settings` | 回収・各種設定 | 回収対象月・提出期限・受付停止・お知らせ、管理者パスコード、営業時間、区分、シフトパターン、割増設定、バックアップ |

### Excel出力
- **シフト表**：部門ごとに1シート（この部門／全部門）。A4横・1ページ幅に収まる印刷設定
- **タイムテーブル**：その日、または月間（日別シート）
- **給与集計**：スタッフ別・部門別・日毎・勤務明細の4シート

### 給与計算ルール
- 実働 ＝ 勤務時間 − 休憩
- 時間外割増：同一スタッフの1日の実働合計（部門横断）が8時間を超えた分に25%（設定で変更・無効化可）
- 深夜割増：22:00〜翌5:00 の勤務に25%（設定で変更・無効化可）
- 休憩：希望の反映・パターン入力時に労基法34条の最低時間（6h超45分／8h超60分）を自動設定。不足時は編集画面で警告
- 休憩時間帯：タイムテーブルで手動登録（ドラッグ／編集ダイアログ／自動配置）。登録すると休憩分数に自動反映し、深夜帯の休憩は深夜時間から控除。配置人数は休憩中を除いて表示
- 交通費：出勤1日につき1回（その日最初のシフトの部門に計上）
- 社会保険料・源泉所得税などの控除前の概算額です。週40時間超の時間外判定は行っていません。

## セットアップ

```bash
cd shift-app
npm install
npm run dev     # 開発サーバー http://localhost:5173
npm test        # 給与計算ロジックのテスト
npm run build   # dist/ に本番ビルド
```

### Supabase（複数端末・複数施設で使う場合・必須）
1. Supabase でプロジェクトを作成（リージョンは **Tokyo** を推奨）
2. SQL Editor で `supabase.sql` を実行（何度実行しても安全です）
3. 「Authentication → Users → Add user」で **本部の管理者**のアカウント（メール＋パスワード）を作成し、SQL Editor で次を実行
   ```sql
   insert into public.hq_members (user_id) select id from auth.users where email = '本部のメールアドレス';
   ```
4. `.env.example` を `.env.local` にコピーして URL と anon key を設定（Vercel / Cloudflare の場合は環境変数に設定）
5. アプリの「管理者」から本部アカウントでログイン →「施設管理（本部）」で施設を作成
6. 各施設の管理者は、Supabase でアカウントを作成 →「施設管理」の施設ごとの「管理者」からメールアドレスを追加

未設定・未セットアップ時はブラウザの localStorage に保存されます（他端末と共有されません。本部・施設のパスコードの初期値は `admin`）。

### 権限と施設の切り替え
| 利用者 | ログイン | できること |
|---|---|---|
| 本部 | メール＋パスワード | 全施設の閲覧・編集、施設の作成・削除、施設管理者の割り当て、全施設の人件費集計 |
| 施設管理者 | メール＋パスワード | 割り当てられた施設だけ閲覧・編集（複数施設の割り当ても可。画面上部で切り替え） |
| スタッフ | 個人PIN（4〜8桁） | 施設のURLからシフト希望の提出・閲覧・取消のみ（時給などは参照できない） |

- スタッフ用URLは施設ごとに `https://（公開URL）/?f=施設コード#staff`。「施設管理」または各施設の「回収・各種設定」からコピーできます。
- データベースの行レベルセキュリティ（RLS）で、他施設のデータは読み書きできません。スタッフはログイン不要の専用関数（`portal_*`）だけを使い、受付停止・期限切れの施設には提出できません。

### 旧バージョン（単一施設）からの移行
- Supabase：`supabase.sql` の末尾「(2) 旧バージョンのデータがある場合」のコメントを外して実行すると、既存データを1つの施設に割り当てます。
- ブラウザ内保存：初回起動時に既存データを「施設1（コード f1）」として自動で移行します。

### スマホのホーム画面に追加（PWA）
- iPhone（Safari）：共有ボタン →「ホーム画面に追加」／Android（Chrome）・PC（Chrome / Edge）：画面上部の「📲 アプリとして追加」
- ホーム画面から開くとアドレスバーのない画面で起動します。オフライン時も画面は表示されますが、データの読み書きには通信が必要です。
- スタッフには施設のURLを開いてからホーム画面に追加してもらうと、次回から自分の施設が自動で開きます。

### デプロイ（Vercel の例）
- Root Directory：`shift-app`
- Build Command：`npm run build` ／ Output Directory：`dist`

### はじめての使い方
1. 管理者画面にログイン（初期パスコード `admin` → 設定画面で必ず変更）
2. 部門マスタ → スタッフマスタを登録（設定画面の「サンプルデータを投入」でお試し可）
3. 設定画面で回収対象月・提出期限を設定し、スタッフ入力画面URLを LINE 等で共有
4. 希望一覧で提出状況を確認 → シフト作成ツールで「希望を一括反映」して調整
5. タイムテーブル・給与計算を確認し、Excel出力

## セキュリティ機能
| 機能 | 内容 | 設定場所 |
|---|---|---|
| スタッフの個人PIN | 希望の提出・閲覧・取消に本人のPINが必要。PINは暗号化した値だけを保存し、管理者も元のPINは見られない。5回続けて間違えると15分ロック | 発行：スタッフマスタ／必須・任意：回収・各種設定 |
| 操作履歴 | データの追加・変更・削除を「誰が・いつ・何を」自動記録（例：時給 ¥1,100 → ¥1,150）。Supabase運用時は管理者も書き換え・削除不可。Excel出力可 | 管理者画面「操作履歴」 |
| 管理者の二段階認証 | パスワード＋認証アプリ（Google Authenticator 等）の6桁コード。本部が「必須」にするとデータベース側で強制 | 画面上部「🔐 二段階認証」 |
| バックアップの案内 | 最後のバックアップから30日以上たつと管理者画面に案内を表示 | 回収・各種設定「データ管理」 |

- 二段階認証を使うには、Supabase の「Authentication → Multi-Factor」で TOTP が有効になっていることを確認してください（標準で有効）。
- 管理者が認証アプリのスマートフォンを紛失した場合は、Supabase の「Authentication → Users」で該当ユーザーの二段階認証を削除してから、再設定してもらいます。
- 操作履歴の保存期間を決める場合は、`supabase.sql` 末尾の削除用SQL（例：3年より前を削除）を定期的に実行します。

## セキュリティ上の注意
- Supabase 運用時は、管理者は Supabase Auth でログインし、RLS により所属施設のデータだけを扱えます。スタッフは時給などを参照できません。
- スタッフは個人PINで本人確認します（PINを「必須にしない」設定にすると、施設のURLを知っている人は誰でもスタッフ名で提出できるため、必須のままの運用を推奨します）。
- ブラウザ内保存モードのパスコードは画面表示を切り替えるだけの簡易的なもので、データは保護されません（試用・デモ向け）。
