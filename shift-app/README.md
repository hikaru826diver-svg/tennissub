# シフト作成WEBアプリ

アルバイトスタッフのシフト希望回収から、シフト表作成・日毎タイムテーブル・給与計算・Excel出力までを行うWebアプリです。
（React + Vite / データ保存は Supabase、未設定時はブラウザ内保存）

## 画面構成

| URL | 画面 | 内容 |
|---|---|---|
| `#staff` | **シフト希望入力**（アルバイト用） | 部門選択 → 氏名選択 → カレンダーで日付を複数選択 → 日毎に希望時間（終日可も可）→ 備考 → 提出。提出済み希望の確認・取消 |
| `#admin-requests` | 希望一覧 | 年月・部門・日付で絞込み。日付別／一覧／**未提出者**表示。希望をワンクリックでシフトに反映 |
| `#admin-shifts` | シフト作成ツール | 部門×月のシフト表。セルクリックで時間・休憩を編集（分割勤務可）、パターン入力モード、希望の一括反映、日別人数・労働時間・人件費、スタッフ別日数・時間・給与概算 |
| `#admin-timetable` | 日毎タイムテーブル | シフト作成ツールのシフトを自動反映した15分単位のガントチャート、時間帯ごとの配置人数 |
| `#admin-payroll` | 給与計算 | 月毎（スタッフ別・部門別）・日毎（部門別）の自動計算 |
| `#admin-staff` | スタッフマスタ | 氏名・フリガナ・区分・時給・交通費（1日）・所属部門（複数可）・在籍状況 |
| `#admin-depts` | 部門マスタ | 部門名・表示色・並び順 |
| `#admin-settings` | 回収・各種設定 | 回収対象月・提出期限・受付停止・お知らせ、管理者パスコード、営業時間、区分、シフトパターン、割増設定、バックアップ |

### Excel出力
- **シフト表**：部門ごとに1シート（この部門／全部門）。A4横・1ページ幅に収まる印刷設定
- **タイムテーブル**：その日、または月間（日別シート）
- **給与集計**：スタッフ別・部門別・日毎・勤務明細の4シート

### 給与計算ルール
- 実働 ＝ 勤務時間 − 休憩
- 時間外割増：同一スタッフの1日の実働合計（部門横断）が8時間を超えた分に25%（設定で変更・無効化可）
- 深夜割増：22:00〜翌5:00 の勤務に25%（設定で変更・無効化可）
- 休憩：希望の反映・パターン入力時に労基法34条の最低時間（6h超45分／8h超60分）を自動設定。不足時は編集画面で警告
- 交通費：出勤1日につき1回（その日最初のシフトの部門に計上）
- 社会保険料・源泉所得税などの控除前の概算額です。週40時間超の時間外判定は行っていません。

## セットアップ

```bash
cd shift-app
npm install
npm run dev     # 開発サーバー http://localhost:5173
npm test        # 給与計算ロジックのテスト
npm run build   # dist/ に本番ビルド
```

### Supabase（複数端末でデータ共有する場合・必須）
1. Supabase の SQL Editor で `supabase.sql` を実行
2. `.env.example` を `.env.local` にコピーして URL と anon key を設定（Vercel の場合は Environment Variables に設定）
3. 起動後、画面上部に「ローカル保存モード」の表示が出なければ接続成功です

未設定・接続失敗時はブラウザの localStorage に保存されます（他端末と共有されないため、スタッフの希望が管理者に届きません）。

### デプロイ（Vercel の例）
- Root Directory：`shift-app`
- Build Command：`npm run build` ／ Output Directory：`dist`

### はじめての使い方
1. 管理者画面にログイン（初期パスコード `admin` → 設定画面で必ず変更）
2. 部門マスタ → スタッフマスタを登録（設定画面の「サンプルデータを投入」でお試し可）
3. 設定画面で回収対象月・提出期限を設定し、スタッフ入力画面URLを LINE 等で共有
4. 希望一覧で提出状況を確認 → シフト作成ツールで「希望を一括反映」して調整
5. タイムテーブル・給与計算を確認し、Excel出力

## セキュリティ上の注意
- 管理者パスコードは画面表示を切り替えるだけの簡易的なもので、通信やデータベースは保護しません。
- `supabase.sql` のポリシーは anon キーで全データを読み書きできる設定です。時給などの個人情報を扱うため、本番運用では Supabase Auth の導入と RLS ポリシーの厳格化（スタッフは自分の希望のみ登録可、管理者のみマスタ・シフト参照可 等）を推奨します。
